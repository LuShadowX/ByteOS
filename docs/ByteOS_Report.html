02 · How it's built

Architecture

ByteOS copies the structure of a real operating system on purpose. A boot sequence hands over to a login screen. A window manager runs apps as processes. All apps share one file system, and that file system enforces permissions.

The layers mirror the "OS architecture" diagram in the syllabus. Applications sit on top. They talk to shared services (the file system and git) instead of touching storage directly, the same way real apps make system calls instead of touching hardware.

1. Permissions (Linux, Unit 3)

vfs.js · lines 125–130export function can(user, node, action) {
    if (user === 'root') return true;
    const shift = node.owner === user ? 6 : 0;
    const bit = { r: 4, w: 2, x: 1 }[action];
    return Boolean((node.mode >> shift) & bit);
}

Each file stores its owner and a mode like 0o644. Root is always allowed. Otherwise the owner gets the first rwx triple and everyone else the last one, and the bit for r (4), w (2) or x (1) is tested.

vfs.js · lines 146–157function walk(path, user) {
    let node = root;
    let seen = '';
    for (const part of path.split('/').filter(Boolean)) {
        need(user, node, 'x', seen || '/');
        if (node.type !== 'dir') throw new FsError(`${seen}: Not a directory`);
        node = node.children[part];
        seen += '/' + part;
        if (!node) throw new FsError(`${seen}: No such file or directory`);
    }
    return node;
}

Like Linux, you need execute (search) permission on every directory along a path. That is why a standard user cannot even list /root, which has mode 700.

2. Shell parsing (Unit 3)

terminal.js · lines 63–73function tokenize(line) {
    const tokens = [];
    const re = /"([^"]*)"|'([^']*)'|(&&|>>|>|\||[^\s|>&]+)/g;
    let match;
    while ((match = re.exec(line))) {
        if (match[1] !== undefined) tokens.push({ value: match[1], quoted: 'double' });
        else if (match[2] !== undefined) tokens.push({ value: match[2], quoted: 'single' });
        else tokens.push({ value: match[3], op: ['&&', '>>', '>', '|'].includes(match[3]) });
    }
    return tokens;
}

A regular expression splits the line into words, quoted strings and the operators &&, |, > and >>. The shell then runs && chains, feeds each pipe stage's output into the next, and writes redirections to files.

Three-way merge: for each file, compare the common ancestor (base), our branch and their branch. If only one side changed it, take that side. If both changed it differently, it is a conflict, and the merge is aborted so nothing is lost.

4. RAID parity (Unit 1)

hardware.js · lines 408–420// GF(2^8) multiply, used for RAID 6's Q parity
function gfMul(a, b) {
    let p = 0;
    for (let i = 0; i < 8; i++) {
        if (b & 1) p ^= a;
        const carry = a & 0x80;
        a = (a << 1) & 0xff;
        if (carry) a ^= 0x1d;
        b >>= 1;
    }
    return p;
}
const gfPow = (n) => { let r = 1; for (let i = 0; i < n; i++) r = gfMul(r, 2); return r; };

RAID 5's P parity is a plain XOR of the data blocks. RAID 6's second parity, Q, multiplies each block by a different power of 2 in the Galois field GF(2⁸). That is how two lost blocks can be solved.

hardware.js · lines 453–461function survives(level, n, failed) {
    const f = failed.size;
    if (level === 0) return f === 0;
    if (level === 1) return f < n;
    if (level === 5) return f <= 1;
    if (level === 6) return f <= 2;
    if (level === 10) { for (let p = 0; p < n / 2; p++) if (failed.has(p * 2) && failed.has(p * 2 + 1)) return false; return true; }
    return false;
}

Fault tolerance per level: RAID 0 survives nothing, RAID 5 one disk, RAID 6 two, and RAID 10 survives as long as no mirror pair loses both disks.

8. Network reachability (Unit 5)

network.js · lines 88–106function reachable(graph, from, failedNodes, cutEdges) {
    if (failedNodes.has(from)) return new Set();
    const seen = new Set([from]);
    const prev = new Map();
    const queue = [from];
    while (queue.length) {
        const cur = queue.shift();
        for (const e of graph.edges) {
            if (cutEdges.has(e.id)) continue;
            const other = e.a === cur ? e.b : e.b === cur ? e.a : null;
            if (!other || seen.has(other) || failedNodes.has(other)) continue;
            seen.add(other);
            prev.set(other, { node: cur, edge: e.id });
            queue.push(other);
        }
    }
    seen.prev = prev;
    return seen;
}

Breadth-first search over cables that are not cut and devices that have not failed. It also records the previous hop, so a packet's route can be drawn. The "survives one cut" check runs this once per cable.

9. Two-factor codes, RFC 6238 (Unit 5)

security.js · lines 190–201export async function totp(secretBytes, time = Date.now(), step = 30, digits = 6) {
    const counter = Math.floor(time / 1000 / step);
    const msg = new ArrayBuffer(8);
    const view = new DataView(msg);
    view.setUint32(0, Math.floor(counter / 2 ** 32));
    view.setUint32(4, counter >>> 0);
    const key = await crypto.subtle.importKey('raw', secretBytes, { name: 'HMAC', hash: 'SHA-1' }, false, ['sign']);
    const sig = new Uint8Array(await crypto.subtle.sign('HMAC', key, msg));
    const offset = sig[sig.length - 1] & 0x0f;
    const code = (((sig[offset] & 0x7f) << 24) | (sig[offset + 1] << 16) | (sig[offset + 2] << 8) | sig[offset + 3]) % 10 ** digits;
    return String(code).padStart(digits, '0');
}

TOTP = HMAC-SHA1(shared secret, number of 30-second steps since 1970), then "dynamic truncation" to 6 digits. It uses the browser's Web Crypto API. It was checked against the official RFC test vectors (94287082 at t = 59 s).

What I learned

  • The OS is a set of rules, not a picture. Making permissions actually block things showed me why x on a directory matters and why root is separated from normal users.
  • Redundancy has a price. The RAID lab made the trade-off clear: RAID 0 is 100% efficient and fragile, RAID 1 is safe and 50% efficient, and parity sits in between.
  • A compiler is just careful steps. Tokens, a tree, then instructions. The compiler vs interpreter difference became obvious when the interpreter printed output before hitting the error.
  • Security is mostly about people and maths. Long passphrases beat clever symbols, salts defeat rainbow tables, and 2FA works because a code depends on both the secret and the time.
  • Git is a graph. Seeing branches and merges drawn live made commits, parents and HEAD click.
